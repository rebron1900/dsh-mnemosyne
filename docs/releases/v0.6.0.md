# v0.6.0

> Release date: 2026-09-01

## Highlights

- Added workspace-scoped memory recall and automatic writes. Workspace identity is explicit and stable through a `.mnemosyne-id` marker and `identity.json`; unbound workspaces never silently fall back to another namespace.
- Added the `mnemosyne_bind` tool plus workspace binding, adoption, rebind, namespace discovery, and migration routes. Migration supports dry runs, SQLite backups, journals, and revert, while keeping legacy session data isolated until the user opts in.
- Added filtered, confirmed batch memory management in the dashboard for veracity, expiry, importance, lifecycle invalidation, and scope moves, including workspace targets and backup-before-mutation protection. Single-memory controls use the same registered batch API.
- Tightened memory deletion to the current namespace or globally visible records, and preserved the existing same-origin, local-only dashboard security boundary.
- Added identity/namespace coverage and expanded host, client, and integration tests for workspace behavior, migration guardrails, dynamic scope configuration, and dashboard management.
- Kept DSH integration metadata compatible with the supported `>=0.1.0-rc.6` host range and restored the required client runtime injection.

## Compatibility and migration

- Existing installations retain session-scoped behavior unless `recallMode` or `autoWriteScope` is explicitly changed. `recallMode=workspace` requires workspace-level automatic writes.
- Workspace mode requires an explicit project binding. Use `mnemosyne_bind` after user consent or bind the project from the dashboard; the plugin refuses `$HOME` and `/` as binding targets.
- Legacy `default` and `dsh_*` rows are not automatically reassigned. Review the dashboard migration tools and create a backup before moving data.
- `dsh-better-sidebar@^0.16.1` remains optional; without it, the core plugin and Settings panel continue to work, but the dashboard tab is unavailable.

## Validation

- `pnpm install --frozen-lockfile --ignore-scripts && pnpm test`: 153 tests passed (136 focused unit/client/identity tests and 17 integration tests).


## Version iteration

- `v0.5.0` introduced the bundled local Memory Dashboard as a read-only inspection surface.
- `v0.6.0` adds explicit workspace memory identity, migration and backup tooling, and confirmed dashboard memory management while preserving session compatibility by default.

## Summary

This release turns the dashboard from an inspection surface into a safe, explicitly authorized memory-management surface and adds project-level memory sharing without silently changing existing session-scoped installations.

## Lazy alternative

Skipped a separate workspace service and database migration layer; add them only if namespace-based isolation no longer meets cross-bank or multi-machine requirements.
